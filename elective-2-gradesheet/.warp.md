# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

This is an ASP.NET Core 8.0 MVC application for managing student grades and automatically analyzing GitHub repository submissions. The app supports two database options (SQLite or SQL Server) and uses a service layer pattern to abstract database operations.

## Build and Run Commands

### Core Development Commands

```bash
# Build the project
dotnet build

# Run the application (development)
dotnet run

# Run with watch (auto-reload on file changes)
dotnet watch run

# Build in release mode
dotnet build -c Release

# Clean the project
dotnet clean
```

### Database Commands

```bash
# Add a new migration (SQL Server only)
dotnet ef migrations add [MigrationName]

# Update database to latest migration (SQL Server)
dotnet ef database update

# Remove the last migration (if not applied)
dotnet ef migrations remove

# Generate SQL script for migrations
dotnet ef migrations script
```

### Database Configuration

The app supports both SQLite (for development) and SQL Server (for production):

```bash
# Check current database provider
grep "Provider" appsettings*.json

# Update appsettings.Development.json for SQLite (development)
# Set "DatabaseSettings:Provider" to "SQLite"

# Update appsettings.json for SQL Server (production)
# Set "DatabaseSettings:Provider" to "SqlServer"
```

## Code Architecture

### Overall Architecture

- **Framework**: ASP.NET Core 8.0 MVC
- **Pattern**: MVC with Service Layer abstraction
- **Database**: Entity Framework Core with dual provider support (SQLite/SQL Server)
- **Frontend**: Server-side rendering with minimal vanilla JavaScript (no frameworks)

### Key Components

1. **Controllers**:
   - `HomeController`: Main application logic, bulk grading workflows
   - `ActivityTemplateController`: Activity template management
   - `SectionController`: Section management

2. **Services** (Business Logic Layer):
   - Interface-based services with database-specific implementations
   - `IGradeService`: Core grading functionality (has SQLite and SQL Server implementations)
   - `GitService`: GitHub repository operations
   - `RepositoryService`: Repository cloning and scanning
   - `RubricScoringService`: Automated code analysis and scoring

3. **Database Strategy**:
   - `ApplicationDbContext`: SQL Server context with migrations
   - `ApplicationDbLiteContext`: SQLite context with auto-creation
   - Different service implementations based on provider (GradeDbLiteService vs GradeDbService)

### Entity Models

- `Student`: Student profile information
- `Section`: Class/course sections
- `ActivityTemplate`: Templates for activities to grade with rubrics
- `StudentSubmission`: Repository submissions and grades

### Bulk Grading Workflow

1. **Select Section** → Server reloads page with available activities
2. **Select Activity** → Server validates rubric and loads students
3. **Enter Repository URLs** → Client-side validation for GitHub URLs
4. **Submit Form** → Server processes, validates, and starts bulk grading
5. **Repository Analysis**:
   - Clone repositories via `GitService`
   - Scan files via `RepositoryService`
   - Score against rubric via `RubricScoringService`
6. **View Results** → Preview, approval, and database updates

### Rubric Scoring

The system can automatically scan student code repositories and score them against predefined rubrics:

- Rubrics are defined in JSON format (see `Samples/websys_basic_csharp_rubric.json`)
- Each rubric item searches for specific code patterns/keywords in specified files
- Points are awarded based on matching patterns
- Results can be reviewed before finalizing grades

## Development Constraints

1. **MVC First**: The application uses traditional server-side MVC patterns over SPAs
2. **Minimal JavaScript**: Uses vanilla JS without frameworks (jQuery dependencies removed)
3. **Database Flexibility**: Code should maintain compatibility with both SQLite and SQL Server
4. **C# ASP.NET MVC Focus**: Primarily used for educational tasks with C# ASP.NET MVC
5. **Server-side Processing**: Progressive enhancement with minimal JavaScript, prioritize server-side validation

## Common Issues and Solutions

### ActivityTemplate Duplicate Records

If you encounter duplicate ActivityTemplate records, ensure:

1. Case-insensitive comparison is used when looking up templates
2. The unique constraint on (SectionId, Period, Name) is maintained  
3. Whitespace is properly trimmed when comparing names

Recent fix: Added unique composite index and case-insensitive string matching in both `GradeDbLiteService.cs` and SQL Server implementation.

### Database Migration Failures

When migrations fail:

1. Check connection strings in `appsettings.json`/`appsettings.Development.json`
2. Verify database provider setting matches your target database
3. For SQL Server, ensure the server is running and accessible
4. For SQLite, verify the `Data` directory exists and is writable
5. SQLite uses auto-creation (`EnsureCreatedAsync()`), SQL Server uses migrations

## Code Style Guidelines

- **Naming**: PascalCase for classes, methods, properties; camelCase for variables
- **Services**: Interface-based with dependency injection
- **Controllers**: Action-based with proper model binding and validation
- **Database Access**: Entity Framework Core with proper error handling
- **Views**: Server-side rendering with Razor, minimal client-side JavaScript
- **Error Handling**: Try/catch blocks with proper exception handling and user-friendly messages
